# 确定功能路线图

> 这里只记录已经确定要做、但尚未全部实现的功能。完成后移入 `PROJECT_CONTEXT.md` 并从本文件删除，不保留过程版本。

## 已完成：完整数据备份与恢复

系统设置“功能扩展”已提供完整加密备份、文件校验和恢复入口。备份覆盖全部 Prisma 业务表（包括配置、敏感密文、会话和操作日志），使用 gzip + AES-256-GCM；恢复前校验格式、结构指纹、管理员密码和 RESTORE 确认词，恢复在单事务中执行，完成后撤销会话并写审计。

后续增强：定时备份、保留数量、附件目录纳入备份、独立测试库演练和磁盘空间预检。

## P0：系统更新

目标：安全更新 Web、API 和数据库结构，任何失败都有明确回滚路径。

必须包含：

- 当前版本、可用版本、发布时间、更新内容和兼容要求。
- 更新包来源校验、哈希校验和签名校验。
- 更新前检查 Node、数据库版本、磁盘、权限、服务状态和待执行迁移。
- 强制执行升级前备份，并确认备份校验通过。
- 维护模式阻止新业务写入，但保留管理员查看更新状态和恢复入口。
- 先准备新版本目录，再运行 Prisma 迁移、切换 API、切换 Web，避免直接覆盖当前版本。
- 更新后执行健康检查、数据库校验和关键业务冒烟测试。
- 失败时自动恢复上一程序版本；数据库迁移不兼容时按备份恢复方案处理。
- 不覆盖 `.env`、数据库、附件、运行状态和管理员自定义配置。
- 更新历史只保存版本结果、耗时和错误摘要，不复制完整聊天记录。

验收：人为制造构建失败、迁移失败、API 启动失败和健康检查失败，系统均能回到可用旧版本或清晰进入可恢复状态。

## P1：收货佬、包裹与物流增强

- 建立收货佬档案和常用地址/联系方式。
- 多笔订单可合并到一个包裹，共用寄件运单号。
- ApiZero Provider Adapter、API Key 加密配置、匿名/认证查询、自动识别、手机号后四位、标准化状态/轨迹、订单列表有值图标和审计已经接通。
- 后续补充收货佬档案、多笔订单合并包裹、更多承运商编码映射、失败重试和持久化查询缓存。

## P1：正式资金流水

- 收货佬回款和给下单人结算建立独立流水。
- 一笔流水可分摊多笔订单，多笔订单可合并付款。
- 保存支付方式快照、凭证、参考号、经办人和时间。
- 订单回款/结算状态由流水汇总，快捷状态操作逐步退出主判断链路。
- 对账、撤销、冲正和审计需要可追踪。

## P1：WPS/Excel 导入

- 提供模板、字段映射、预览、逐行校验和错误下载。
- 同批次单行失败不影响其他合法行；重复订单有明确规则。
- 金额、日期、枚举、昵称、平台和品类均按当前有效字典校验。
- 导出保持暂缓，直到业务字段和权限稳定。

## P2：官方联盟与消息分发

- 淘宝联盟、京粉、唯享客等按统一 `AffiliateAdapter` 接入。
- 官方接口只处理对应平台；第三方聚合接口可识别多个平台。
- Token 到期提醒、更新记录和转换失败重试。
- Bot 通过 API 和事件队列分发转换结果、待审核和异常提醒。
- 对接建议见 `docs/wechat-bot.md`。

## 开发门槛

每个路线图功能进入开发前必须明确：

- 数据模型和迁移。
- API、权限、限流、审计和错误码。
- 真实持久化与失败恢复。
- 亮暗主题、移动端和空/错/加载状态。
- 单元测试、关键集成测试和上线回滚方式。

不接受只显示“即将上线”的空页面或只有前端状态的假开关。
