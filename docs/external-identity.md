# 微信 H5 外部身份设计

## 目标

每个方案链接可以被多人在微信内打开。系统需要自动区分访问者，使其只能管理自己的审核前订单并查看自己的回款状态。

## 第一版：设备身份

普通 H5 页面不能直接读取微信号或 `openid`。首次访问时由服务端：

1. 创建随机外部身份。
2. 生成设备候选码，例如 `WX-8F2K7M9P4Q`。
3. 生成高强度会话 Token。
4. 数据库只保存 Token 哈希。
5. 浏览器保存 `HttpOnly + Secure` Cookie。
6. 首次公开提交微信昵称时将设备绑定到下单人档案；如果该档案还没有唯一识别码，则使用设备候选码补充。

同一微信设备再次打开相同域名下的其他方案链接时，Cookie 会自动带上，因此无需再次选择身份。

本项目第一版确认不要求访问者填写姓名、手机号或其他身份资料。设备身份只负责自动识别；对外查询使用下单人档案中的唯一识别码。

后台手工新增或后台订单自动建立的下单人识别码保持为空。下单人首次公开提交微信昵称后才生成唯一识别码；未携带微信昵称的公开入口也不能提前写入设备候选码。识别码可以作为只读历史查询凭证，但不能修改或删除订单、回款资料。

## 第二版：微信 OAuth

当具备公众号或企业微信条件后：

```text
打开方案链接
  → 微信 OAuth
  → 获得 openid/unionid
  → 查找或创建外部身份
  → 与已有设备身份及下单人档案合并
```

OAuth 可以真正做到同一微信用户跨设备识别。需要配置稳定 HTTPS 域名和微信授权回调域名。

## 数据关系

```text
下单人 Submitter
  ├─ 微信 OAuth 身份
  ├─ 手机 A 的设备身份
  └─ 手机 B 的设备身份

外部身份 ExternalIdentity
  ├─ 多个会话 IdentitySession
  └─ 多笔外部提交订单
```

## 失效与恢复

- 管理员可以禁用某个身份或撤销全部会话。
- 清理微信缓存或更换设备后会创建新设备身份；下单人输入原唯一识别码即可恢复只读查询并绑定新设备。
- 身份合并只改变归属，不删除原始订单和审计记录。
