# 当前有效产品需求

> 本文件只保存现行要求。新要求直接修改对应条目；被替代、重复或已取消的内容立即删除。

## 1. 项目与角色

系统用于替代 WPS 订单登记，覆盖下单、寄件、收货佬回款、给下单人结算和利润管理，适配电脑、手机及微信内置浏览器。

- 管理员：管理全部订单、审核、资金状态、配置、统计和审计。
- 下单人：使用微信昵称报单、登记回款资料并只读查询本人订单。
- 收货佬：作为货物去向及管理员应收款对象。

## 2. 订单数据与状态

- 一行代表一笔订单，不按商品数量拆单。
- “下单账号”与“下单人”是同一字段，使用微信昵称；不存在时自动建立下单人档案。
- 商品字段统一为“商品/方案*数量”，支持多行；删除独立数量字段及兼容字段。
- 支付方式为自己付、代付、其他；选择其他时必须填写说明，默认自己付。
- 核心订单资料包括日期、平台、下单人、品类、商品、订单号、平台运单号、下单地址、收货佬、寄件运单号、支付方式、下单金额、支付优惠、结算金额、回款金额、扫码返利、备注、修改说明和扩展字段。
- 扫码返利保存原始扫码金额；未扫码时实际金额为 0，扫码时实际金额只读计算为原始金额 × 0.9。
- 寄件状态：未寄出、已寄出、已签收、异常。
- 回款状态：未回款、已回款、异常。
- 结算状态：未结算、已结算、异常。
- 三套状态独立保存；收货佬标记已回款时可按现有规则同步已签收，给下单人结算不得修改回款状态。
- 新订单默认排在最前；展示序号连续，并支持正序/倒序。
- 编辑订单可修改全部订单资料、资金状态并软删除订单。
- 修改说明默认空白；每次非空修改按时间追加，支持一次清空全部说明。

## 3. 订单列表与录入

- 新建、编辑和批量添加均使用紧凑响应式弹窗。
- 批量添加的可录入表头从订单列表字段元数据动态生成，不单独维护旧固定列；支付方式的具体说明合并在“支付方式”列内，不建立“其他说明”列。
- 粘贴 WPS/Excel 数据时，有表头按订单列表列名匹配且不限制列顺序，多余的序号、状态、利润等只读列自动忽略；无表头时按页面实时显示的列模板识别。
- 日期提供今天、昨天和上一单快捷值；地址等常用内容支持快捷复用。
- 数字和金额只允许直接键入，不显示任何加减按钮；金额允许整数或最多两位小数，不限制为整数或 10 元步进。
- 列设置动态包含核心字段及启用的扩展字段，支持显示、隐藏、排序和调整宽度。
- 筛选使用服务端查询；不同字段之间为 AND，同一字段多选为 OR。
- 当前不增加支付方式筛选。
- 支持日期、金额、分类、状态、文本和扩展字段筛选。
- 筛选后显示全部命中订单的总结算金额、总利润和总回款金额，不受分页限制。
- 勾选订单后整行及固定列同步高亮；双向结清订单仍可勾选。
- 批量已回款只更新回款相关数据；批量已结算只更新结算相关数据。
- 给下单人批量结算时只允许选择同一下单人的订单。
- 可选择复制平台运单号或寄件运单号；每个订单一行，同一订单多号使用 `&`，保留空行且不去重。
- 操作与审核合并在表格末尾；行内操作使用统一低饱和圆角操作组。
- 表格少量数据时直接完整显示，超过可视高度后才内部滚动。
- 订单列表仅导出 `.xlsx`：存在勾选订单时导出勾选项；未勾选时导出当前全部筛选结果且不受分页限制。
- 导出字段及顺序与当前列设置一致并包含扩展字段；金额保持数字和金额格式，订单号、运单号等标识保持文本。
- 导出文件名使用 `订单列表_所选订单/筛选订单/全部订单_时间.xlsx`；WPS/Excel 导入保留为后续任务。

## 4. 在线报单

- 每个在线报单模板拥有独立固定链接、Token 和二维码。
- 新建公开标题默认为“在线报单系统”，管理员可修改。
- 分享表单只配置链接状态、标题、富文本填写说明、字段权限和默认规则。
- 方案名称、多行方案内容和方案说明在公开报单页作为只读方案信息展示，不写入或显示在订单列表。
- 方案管理不维护固定品类；公开报单里的品类仍是订单实际字段，由字段权限控制，可由下单人填写或管理员补充。
- 字段从订单列表当前有效分类动态加载，管理员用紧凑卡片设置隐藏、只读、可填写和必填。
- 没有填写的字段保持空白，管理员可在确认前补充。
- 富文本说明支持加粗、斜体、下划线、字号和颜色；保存、重新打开及公开页必须保留格式，服务端执行白名单过滤。
- 支付方式使用横向三卡片；扫码返利使用横向双卡片。
- 外部提交先进入待确认；管理员确认后才进入正式订单流程。
- 管理员可配置确认前是否允许下单人修改或删除；确认后锁定。
- 报单链接显示当前识别码，并允许重新输入原识别码绑定新设备。
- 方案列表和配置弹窗必须适配统一亮暗主题。

## 5. 下单人身份

- 识别码归属于下单人档案，不归属于设备；同一下单人始终只有一个识别码。
- 后台手工建立且从未公开提交的下单人可暂时没有识别码。
- 首次公开提交微信昵称并成功关联后补充识别码。
- 有效 Cookie 必须持续复用原身份；一个下单人可绑定多台设备。
- 新设备可手动输入原识别码恢复关联，之后自动进入本人页面。
- 微信昵称与已绑定的其他档案冲突时提交失败，不自动覆盖或合并。
- 识别码仅用于只读查询和身份恢复，不能修改已确认订单或资料。

## 6. 回款登记

- 回款登记使用下单人微信昵称，不记录下单平台或独立平台账号。
- 支持同时选择微信转账、支付宝和银行卡转账。
- 微信转账直接使用微信昵称；支付宝填写支付宝账号；银行卡填写真实姓名、银行和卡号。
- 未选择的方式不显示、不校验对应字段。
- 支付宝账号和银行卡号加密保存，列表默认脱敏。
- 后台手工添加资料时识别码可为空；公开提交后按身份规则补充。
- 回款登记提供独立长期链接及独立填写开关。
- 外部资料提交后进入待确认；管理员确认后禁止再次公开修改，并提示联系管理员。
- 删除下单人时只统计有效订单；存在有效订单或资金流水时禁止删除。

## 7. 订单查询

- 订单查询使用独立链接、Token 和开关，与回款填写完全不联动。
- 已识别设备自动进入本人查询；识别失败时允许手动输入识别码。
- 查询只读，不提供编辑、删除、审核或回款资料修改。
- 管理员可从订单列表当前有效分类中动态选择客户可见字段，并可单独锁定或解锁后台专用字段。
- 服务端不得返回被关闭的字段。
- 默认业务范围包括下单时间、商品/方案、平台运单号、寄件运单号、下单金额、结算金额和结算状态。
- 查询结果分页显示，回款账号只返回脱敏内容。

## 8. 利润规则

- 利润公式：回款金额 - 结算金额 + 支付优惠 + 实际扫码/平台返利。
- 收货佬未标记已回款时，订单列表已结算利润显示 0。
- 规则由后台配置并版本化；订单保存规则 ID、版本和公式快照。
- 样例试算只显示当前实际使用字段，不显示已取消的部分回款、运费、手续费和其他收支输入。
- 订单列表用一个利润分类上下显示已结算利润与灰色预结算利润。

## 9. 返利平台与转换

- 基础设置中的“返利平台配置”只维护接口类型、启用状态、API 地址、Token、Device、Key、Secret 和推广位。
- 第三方聚合与官方联盟使用统一卡片选择；官方接口只能转换对应平台。
- 梨花熊为首个真实 Adapter，支持淘宝、京东、唯品会、拼多多、抖音、快手、美团、闪购、团购等。
- 梨花熊 `device` 可配置；PC Token 使用 `pcweb`，APP Token 使用 `web`。
- Token、Key、Secret 等敏感值加密保存，前端不回显明文。
- “返利转换”是独立功能页：左侧输入，右侧结果；窄屏改为上下布局。
- 二维码必须根据最终转换结果原文生成，不使用其他链接字段。
- 转换成功和失败均保存历史；支持复制、单条删除和清空。
- 官方联盟接口和 Bot 分发后续逐个接入。

## 10. 总览与设置

- 业务总览只显示关键金额、待处理事项和最近订单；系统信息统一在系统设置的运行状态中展示。
- 待办卡片点击后进入带对应筛选条件的订单列表。
- API 接口目录使用独立页面自动读取 OpenAPI，新增接口自动出现；业务总览不重复展示运行信息。
- 基础设置只放业务配置；系统设置支持自定义系统名称、管理员后台外网访问控制、动态域名白名单、后台安全入口、Web/API/数据库运行状态、API 真实重启、数据库业务访问开关、访问安全和管理员设备会话管理，并承载备份、通知、物流等后续系统能力。
- 数据库业务访问关闭后，订单、报单、回款、查询和返利等业务接口立即停止读写；登录、系统设置和恢复开关保持可用，开关状态在 API 重启后仍保留。
- 本机回环地址始终允许访问后台；后台外网访问关闭时只拦截登录、管理员页面、管理 API 和 Swagger 文档。在线报单、回款登记、订单查询页面及其公开 API 不受后台开关影响，继续由各自链接状态或独立开关控制。
- 外部使用域名访问任何页面时，域名必须精确命中系统白名单或通配域名；局域网/公网 IP 可直接访问。公开系统状态接口始终返回名称及对应访问判断。
- Vite 接收动态 Host，最终域名权限以后端数据库配置为准；受限后台页面每 5 秒重新读取访问状态，管理员修正开关或白名单后自动恢复。
- 管理员浏览器生成稳定设备指纹；同一管理员在同一设备通过不同域名、局域网 IP 或反向代理入口登录时归并为一个设备，并显示该设备访问过的地址数量。历史会话没有指纹时按 User-Agent 兼容归并；设备名称显示“操作系统 + 浏览器”，支持管理员重命名、按设备注销和退出其他设备。
- 系统设置提供完整及选择性数据备份与恢复：默认完整备份，也可多选订单列表、下单人与回款、平台与在线报单、接口配置、返利历史、系统与管理员、操作日志。订单等分类自动附带外键所需引用数据；引用数据在局部恢复时只补齐，所选主数据按主键合并/覆盖，不清空未选模块。完整恢复替换全部数据并撤销会话；恢复前统一校验格式、管理员密码和 RESTORE 确认词，恢复结果写入审计。备份使用 DATA_ENCRYPTION_KEY 加密并 gzip 压缩，兼容读取 V1 完整备份。
- 订单列表的平台运单号和寄件运单号在有值时显示快递查询图标；查询使用系统设置中配置的 ApiZero 快递接口，支持自动识别、可选承运商编码和顺丰/中通等场景的手机号后四位，结果包含承运商、状态、更新时间和轨迹，无运单号不显示图标。
- 系统设置提供“域名首页访问处理”：外部用户只访问 `/` 时可配置为显示 404，或跳转到管理员填写的完整 http/https 地址；本机访问 `/` 仍进入后台。
- 缺少 Token 的 `/form`、`/payout`、`/order-query`，错误路径、失效链接及其他未知地址始终显示 404 或对应业务失效页面，绝不跳转管理员登录。本机明确访问 `/login` 或有效 `/admin/...` 路径时进入后台认证流程。
- 全新安装不随机生成且默认不启用后台安全入口，管理员可直接访问 `/login` 或 `/admin` 完成首次登录。管理员在系统设置中手动填写并保存入口后，外网直接访问 `/login`、`/admin`、管理 API 或接口文档统一返回 404，必须先访问配置的单段安全入口。入口标识为 5 至 12 位字母和数字且必须同时包含两者；正确入口由服务端验证并写入 HttpOnly HMAC 签名 Cookie，公开设置不返回真实入口；入口修改后旧授权失效，清空入口并保存可关闭保护。本机回环地址不受入口限制。
- API 收到 Docker 的正常停止信号时应先关闭 NestJS 和数据库连接，再以成功状态退出，避免管理面板把手动停止误报为退出码 143。
- 新建和修改管理员密码最短 6 位；登录仍兼容校验已有密码，部署时建议使用更长且唯一的密码。
- 系统操作日志真实读取审计数据，支持分页、筛选、详情及二次确认清空；清空后保留本次清空记录。

## 11. UI 固定规则

- 全系统使用统一圆角、半透明、柔和渐变及亮暗主题。
- 全局基础字号统一；订单列表保持适合高密度表格的字号，公开报单和查询页适当放大。
- 选择卡片使用统一 `.card-choice`，选中状态不显示右上角对勾。
- 所有数字输入框全局隐藏 Element Plus controls 和浏览器原生微调按钮。
- 页面边框、辅助文字和分隔线必须使用主题变量，不写死亮色值。
- Element Plus 与 VXE Table 的固定列使用不透明主题背景并关闭边缘阴影，禁止重影、透色和主题外白边。
- 固定操作列表头与相邻表头保持同色。
- 新页面必须复用现有主题组件和变量，不单独发明视觉体系。

## 12. 数据、安全与审计

- 本机数据保存在 `.local-data/pglite`，程序、数据库和附件分开保存。
- 订单删除默认软删除；关键新增、修改、删除、审核和状态变化记录审计。
- 金额使用数据库定点数或最小货币单位。
- 收款账号使用应用层加密；公开接口限流、校验并防重复提交。
- 高强度 Token 数据库只保存哈希；Cookie 使用合适的 HttpOnly、Secure 和 SameSite。
- 不在仓库或普通日志保存密码、Token、账号明文或生产密钥。
